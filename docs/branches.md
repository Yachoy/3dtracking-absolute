# Сравнение с веткой `baseline-online-tracker`

В репозитории параллельно развивалась ветка `baseline-online-tracker`
(4 коммита от `46e1611`, файлы `run.py`, `evaluate.py`, `tracker/*`,
`tools/*`, разбор задачи в `docs/razbor.md`). Ветка `mat-htt` пустая —
только начальный коммит. Здесь — что там сделано, что мы взяли и что
имеет смысл взять дальше.

## Что там есть

| блок | как сделано |
|------|-------------|
| детектор | YOLO26s (ultralytics), классы car/bus/truck, imgsz 1280, кэш в CSV |
| измерение | середина **нижнего** края рамки + высота рамки `h`, `дальность ≈ fy·H/h` — одна камера даёт полную 3D-точку |
| фильтр | EKF в 3D, постоянная скорость, `accel_xy = 12 м/с²`, хи-квадрат гейт по инновации, обновление по камерам последовательно |
| ассоциация | по прогнозу трека: в каждой камере берётся детекция, попавшая в зону перепроекции |
| модель объекта | FBX `CargoTruck`, выпуклая оболочка, масштаб и точка-ответ подобраны МНК по рамкам; сравнение всех 4 краёв рамки, якобиан только по позиции |
| пропуски | Median Flow: сетка точек, LK вперёд-назад, вычитание поворота камеры гомографией; вперёд — онлайн, назад — с задержкой |
| жизненный цикл | tentative → confirmed (5 обновлений) → lost (3 с без измерений) |

Их результаты (тестовый набор, MAE 3D): v0 центр рамки 13.9 м → v1 низ+высота
10.8 м → v2 accel 12 м/с² 9.8 м → v3 +оптический поток 9.0 м (покрытие 99.5%)
→ v4 +3D-модель 7.2 м (median 4.8, p90 15.8).

## Что мы взяли

1. **Измерение по точке касания земли, а не по центру бокса** —
   `Detection.ground_point` в `core/detect.py`.
2. **EKF в 3D с хи-квадрат гейтом** — `experiments/e02_ekf.py`.
3. **Параметры эксперимента из CLI** (`--param k=v`, `--tag`) — иначе
   абляции затирают друг друга в `out/`.
4. **Калибровку точки-ответа**: смещение «центр бокса → GT» подобрано по
   данным и вынесено в параметры (`answer_fwd_m`, `answer_up_m`).

## Что получилось (и не получилось)

| вариант | median | MAE | RMSE |
|---|---|---|---|
| e00 oracle (σ=1.5 px) | 0.13 | 0.16 | 0.20 |
| e01 motion, смещение из модели | 5.59 | 7.53 | 9.83 |
| e01 motion, калиброванное смещение (11.3 м вперёд, −0.28 м вверх) | **5.30** | **7.32** | **9.77** |
| e02 EKF по 3D-точкам (первая версия) | 33.3 | 46.8 | 57.7 |
| e02 + реалистичный шум измерения и сброс трека | 11.7 | 14.1 | 15.7 |

**Вывод: наивный EKF поверх 3D-точек делает хуже.** Причина не в фильтре,
а в измерении: ковариация триангуляции не отражает смещение центра
силуэта (2–10 м), фильтр начинает доверять своему прогнозу, гейт по
перепроекции перестаёт находить детекции, и трек «уезжает» — ошибка
растёт до 20–30 м. Лечится это не подбором шума, а сменой измерения:
у них EKF обновляется **в пикселях** (u, v_низа, h) — там и шум
физически осмысленный, и одна камера даёт дальность.

## Что имеет смысл взять дальше (по убыванию эффекта)

1. **Детектор YOLO вместо вычитания фона.** У нас бокс = силуэт вместе с
   тенью и без уверенности; у них — плотная рамка объекта и `conf`.
   Это же снимает главную проблему e01: бокс «плывёт» по ракурсу.
2. **EKF в пиксельном пространстве** (u, v_низа, h) с шумом, зависящим от
   размера рамки — тогда одиночная камера даёт полноценное измерение, а
   покрытие уходит с 73% к ~99%.
3. **Заполнение пропусков оптическим потоком** (Median Flow + вычитание
   поворота камеры гомографией) — у них это дало +6% покрытия и −0.8 м MAE.
4. **Сравнение 4 краёв рамки с проекцией 3D-модели**, направление — из
   скорости (рамка не должна влиять на скорость). У нас уже есть модель
   тягач+прицеп, не хватает оптимизации по краям.

Отдельно: их калибровка даёт высоту фуры 8.9 м и точку-ответ 3.9 м над
землёй (модель FBX в сцене, похоже, увеличена), у нас по рамкам сходится
точка-ответ 1.7 м над землёй при габарите 4 м. Это разные предположения о
том, где лежит GT-точка; обе калибровки дают схожий порядок ошибки, но
наша согласуется и с моделью кабины, и с фактическим положением колёс.
